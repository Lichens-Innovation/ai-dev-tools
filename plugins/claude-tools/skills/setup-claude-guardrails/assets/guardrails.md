# Guardrails

A PreToolUse hook, deny rules and usually a sandbox are active. After a denied call, change approach instead of retrying; if that's impossible, tell the user what is missing.

- Missing tool (e.g. `Glob`): use `find`/`ls` via Bash or `Grep`. `Write` fails on an existing file you haven't read: `rm -f` it first.
- The hook scans the whole command; a `/` or `~/` in a string counts as a path. Message text without `$` or backticks is skipped (`git commit -m '…'`, `-F - <<'EOF'`, `gh`/`glab` `--title|--body|--notes|--description`). Put other path-heavy text (scripts, JSON) in a file made with `Write`.
- Never `cd`, even inside the project: a read after a `cd` can't be checked against the read block, so the user must approve it even in auto mode. Use relative or absolute paths, `git -C <dir>`, the tool's own flag (`-C`, `--root`, `--prefix`, `--cwd`) or `pnpm --filter <pkg>` / `npm -w <pkg>`.
- Run programs by name from `PATH`, not `~/.local/bin` or `/Applications`. Run project tools as `node_modules/.bin/<tool>`, `pnpm --filter <pkg> exec <tool>` in a workspace, or `node <script>`. Never `npx`: it can contact the npm registry and downloads a missing package (if unavoidable: `NPM_CONFIG_UPDATE_NOTIFIER=false npx --no-install`). Temp files go in `/tmp/claude-<uid>/` (the sandbox's `$TMPDIR`), the only temp dir the read block allows.
- A command leaves the sandbox (`gh`, `glab`, `git push|pull|fetch`, `open`) or matches an allow rule (e.g. `node *script.cjs*`) only if every command in the call does. A `cd`, `;`, pipe, `2>&1`, redirection, heredoc, backtick, `$(...)` or extra command, even quoted, blocks the lot. One command per call (independent ones in parallel); only excluded commands may be joined, with `&&`.
- Commit in one call, then `git push -u origin HEAD && gh pr create --title '…' --body '…'` in another (`'\''` for an apostrophe). A body with backticks, `$` or code goes in a `Write` file passed with `--body-file`; outside the sandbox `$TMPDIR` differs, so pass the real `/tmp/claude-<uid>/...` path. If `open`/`osascript` still fails, tell the user to run it with `!`.
- `git push`/`gh`/`glab` failing with `proxy requires authentication` or `Could not read from remote repository` means the call stayed in the sandbox: rebuild it as above and retry once.
- The sandbox can't write `.git/config`: tracking fails with `could not lock config file .git/config: Operation not permitted`, and `git checkout -B` can leave a half-done checkout (check `git status`). Use `git switch [-c] <branch>` without `-t`/`--track`; `git push -u` is fine.
- Bash can't read most of `~/.claude`, including large tool outputs under `~/.claude/projects`: use `Read` with `offset`/`limit`.
- Stay in the project and its `additionalDirectories`; ask for anything else. Never read or edit `.env*` (except `.example|.sample|.template|.dist`), `~/.claude.json` or `.credentials.json`, and don't dodge the check.
- An `ask` on settings or hook files is intentional: explain and wait.
- A guardrail that keeps costing you steps, or is unclear: finish the task, then tell the user and suggest improving it (`/setup-claude-guardrails` ships the rule and hook). Don't work around it.
